### LLVM 22 API Deviations from nvvm_recipes.md

`nvvm_recipes.md` targets LLVM 17/18. Confirmed differences in LLVM 22:

1. **`lookupTarget`**: String overload deprecated; must use `llvm::TargetRegistry::lookupTarget(llvm::Triple, err)`.
2. **`createTargetMachine`**: First arg must be `const Triple&`, not `const char*`.
3. **`llvm.nvvm.barrier0`**: **Removed.** Not present as a `def` in `IntrinsicsNVVM.td`.
   The comment in the .td file documents: `barrier0 -> barrier.cta.sync.aligned.all(0)`.
   Replacement call: `int_nvvm_barrier_cta_sync_aligned_all` with `i32 0` arg, or use
   `M.getOrInsertFunction("llvm.nvvm.barrier.cta.sync.aligned.all", ...)`.
4. **`int_nvvm_read_ptx_sreg_tid_x`**: Defined via `defm int_nvvm_read_ptx_sreg_tid : PTXReadSRegIntrinsic_v4i32`.
   The `_x` suffix is generated by defm expansion. The enum ID must be verified at compile
   time against the actual generated headers.
5. **Opaque pointer mode**: LLVM 22 is fully opaque-pointer. `PointerType::get(C, AS)`
   takes only context and address space; no element type arg.
